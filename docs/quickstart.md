# От распаковки до первого результата

Этот справочник читает агент настройки. Владельцу достаточно двух заданий из
[README](../README.md), ответов на недостающие вопросы и просмотра результата.

## 1. Подготовить профиль

Проверь существующий Python 3.11+ командой `python --version`. На Windows имя
команды может быть `py -3`, на Linux — `python3`. Новые библиотеки через pip
для самого пакета не требуются. Для конкретного сайта сохраняются его обычные
зависимости и команды сборки.

Из корня распакованного пакета:

```sh
python seo.py --project "../my-seo-state" init
python seo.py --project "../my-seo-state" demo
python seo.py --project "../my-seo-state" doctor
```

`my-seo-state` — отдельная личная папка. Не создавай её внутри публичного
репозитория. Используй один и тот же абсолютный путь при дальнейших запусках,
особенно в расписании.

`init` создаёт профиль, `.gitignore`, `.env.example`, пустые поля `.env` и
`business.md`. Заполни профиль по документам владельца: домен, язык, рынок,
регион, устройство, часовой пояс, блог, автор и модель. В `business.md` помести
проверенные сведения о продукте, задачах аудитории и ограничениях. Персональные
данные клиентов и секреты туда не включаются.

Владелец самостоятельно вводит нужные ключи в `.env`; остальные поля остаются
пустыми. На Linux ограничь чтение личной папки нужной учётной записью; на Windows
проверь NTFS-права. `.gitignore` защищает от случайного Git-добавления, но не
заменяет права доступа и резервирование.

## 2. Получить первый отчёт

Выбери модули по [таблице доступов](providers.md). Без поисковых панелей можно
начать с публичного обхода своего сайта; он тоже требует разрешённых запросов.

Сначала согласуй дневные ограничения `requests_per_day`, `model_calls_per_day`,
`output_tokens_per_day`, `articles_per_day`, `updates_per_day`, а также максимальный вход и выход
модели. Ноль блокирует действие. Это ограничители количества операций, **не
денежный счётчик**: бюджет в валюте дополнительно ограничивается у провайдера.
Резерв на неясно завершившийся запрос не освобождается автоматически.
Для Codex резерв токенов не является жёстким ограничением фактического выхода;
подробности и ограничения изоляции — в [описании моделей](providers.md).

```sh
python seo.py --project "../my-seo-state" report --live
```

В `reports/` появятся Markdown для чтения и JSON с наблюдениями. Модуль без
ключей или успешного ответа отмечается как непроверенный. Пустая панель нового
сайта не означает нулевой спрос.

`report --live --weekly` добавляет настроенные сравнения конкурентов, PageSpeed
и импорт GEO-наблюдений. `--strategy` дополнительно вызывает модель в рамках
лимитов; обычный отчёт не зависит от ответа модели. Проверь, что модель получает
только необходимые данные, и разреши этот вызов отдельно при первом запуске.
Чтобы включить стратега в плановый отчёт, отдельно согласуй расходы и установи
`schedule.strategy_enabled: true`. По умолчанию он выключен.

Если нужен Telegram, проверь получателя и тестовое сообщение по его явному
согласованию. Команда доставки — `deliver --live`. Не передавай отчёты в чужие
чаты, оставшиеся от примеров или старых проектов.

## 3. Провести контрольную публикацию

Агент настраивает [адаптер сайта](site-adapter.md), затем готовит CSV по
`examples/topics.csv` из уже собранной семантики. Связи запрос → кластер →
страница сохраняются; занятые интенты не становятся новыми конкурирующими URL.

```sh
python seo.py --project "../my-seo-state" import-topics "../my-seo-state/inputs/topics.csv"
python seo.py --project "../my-seo-state" sources-approve https://example.org/source
python seo.py --project "../my-seo-state" research topic-001 --live
python seo.py --project "../my-seo-state" draft topic-001 --live
```

Адрес и ID в примере заменяются фактическими значениями. `sources-approve`
фиксирует уже полученное решение владельца о конкретных адресах. Не добавляй
источники автоматически ради прохождения проверки.

В `drafts/topic-001/` сохраняются источники, бриф, ответы автора и редактора,
MDX и медиа. Покажи владельцу текст, факты, ссылки, автора и вид в тестовом
блоге. После его одобрения:

```sh
python seo.py --project "../my-seo-state" approve topic-001
python seo.py --project "../my-seo-state" publish topic-001 --live --allow-publish
```

Проверь URL, заголовок, canonical, доступность для обхода, версию `seo-revision`,
наличие в sitemap и медиа. Сохрани квитанцию. Посмотри страницу в браузере на
мобильной и широкой ширине; автоматическая проверка HTML не оценивает всю вёрстку.

## 4. Включить согласованный режим

После приёмки пробной статьи:

```sh
python seo.py --project "../my-seo-state" activate --trial topic-001 --content --reports
python seo.py --project "../my-seo-state" schedule
```

`activate` меняет разрешения профиля; `schedule` показывает команду для внешнего
планировщика. Ни одна из них сама не устанавливает cron и не запускает постоянный
процесс. Установи показанную команду только после поручения владельца и проверки
существующих заданий. Для Linux используй выделенного пользователя, абсолютные
пути и один издатель. Windows может выполнять ручные запуски; автоматическую
работу настрой отдельным заданием планировщика и проверь под его учётной записью.

`tick --live --allow-publish` выполняет подходящую работу одним запуском и
завершается. Компьютер или сервер должен быть включён. В профиле заданы часовой
пояс и окна запуска. Не добавляй второе расписание в GitHub Actions параллельно
уже работающему серверному издателю.

## Продолжение после перерыва

```sh
python seo.py --project "../my-seo-state" status
python seo.py --project "../my-seo-state" pause
```

Пауза запрещает новые автоматические старты; уже начатый процесс она не убивает.
Сначала прочитай статус и [порядок восстановления](recovery.md). Не выбирай
«последнюю» личную папку автоматически и не выполняй `init` поверх рабочего
профиля. При пустой очереди проверь кандидатов из отчёта и импортируй следующую
согласованную порцию кластеров.
