# Пауза, продолжение и резервирование

Всегда указывайте ту же личную папку `--project`. Состояние очереди и квитанции
важнее последней строки в терминале. Не создавайте новую тему или operation_id
только потому, что прежняя команда не успела вернуть ответ.

## Сначала статус

```sh
python seo.py --project "../my-seo-state" pause
python seo.py --project "../my-seo-state" status
```

Пауза отключает новые автоматические старты. Уже начатый процесс она не убивает.
Дождитесь его результата либо установите, что он завершился. Не удаляйте
блокировку активного PID и не запускайте второй издатель поверх первого.

## Выберите ситуацию

| Ситуация | Следующее действие |
|---|---|
| Лимит равен нулю или исчерпан | Проверить `profile.json` и учёт дня; не повышать бюджет без решения владельца |
| Не хватает ключа или доступа | Владелец вводит значение в `.env`; затем ограниченная согласованная live-проверка |
| Источник не читается или перенаправляет на новый адрес | Согласовать конечный адрес либо другой источник, затем повторить исследование |
| Автор/редактор остановился | Прочитать сохранённые замечания и доказательства; исправить причину, не обходить проверку |
| Входы изменились после генерации | `restart-draft TOPIC` архивирует этапы для нового прохода; исходная версия остаётся для сверки |
| Потерян ответ при публикации | `publish-status TOPIC --live`; сначала сверка той же операции на стороне сайта |
| Сайт принял статью, сообщение не пришло | Проверить очередь доставки; повторно статью не публиковать |
| Публикация конфликтует с текущим файлом | Сравнить актуальные хеши, правки владельца и историю; не сбрасывать checkout |
| Процесс аварийно завершился и оставил блокировку | Проверить, что записанный PID действительно не работает; затем `unlock --pid PID` |

`restart-draft` не предназначен для обхода неопределённой публикации. Сначала
разрешите состояние сайта. Если изменился источник или модель, повторный проход
может потратить новый бюджет: согласуйте его до `--live`.

## Неопределённая публикация

```sh
python seo.py --project "../my-seo-state" publish-status topic-001 --live
```

Bridge хранит квитанцию по operation_id. Если релиз действительно появился,
проверка переводит его в принятый статус. Если живой URL не соответствует
ожидаемой версии, неопределённость сохраняется — она не разрешает ещё один
deploy автоматически. Сверьте журнал развёртывания, версию страницы и файлов.

При необходимости отката владелец согласует действие, а агент проверяет,
не изменил ли кто-то затронутые файлы после выпуска:

```sh
python seo.py --project "../my-seo-state" rollback topic-001 --live --allow-publish
```

Откат восстанавливает относящиеся к операции файлы и выполняет заранее
настроенную команду сайта. После этого проверьте реальную предыдущую версию,
ссылки и доступность сайта. Квитанция отката не заменяет эту проверку.
Чужие последующие изменения требуют ручного согласования, а не перезаписи.

## Неопределённая доставка

Обычный `deliver --live` обрабатывает ожидающие уведомления. Если внешний сервис
мог принять запрос, но ответ потерян, запись имеет статус `unknown` и без
решения владельца не повторяется.

Проверьте чат или поисковую панель. После согласования повторной попытки:

```sh
python seo.py --project "../my-seo-state" deliver --live --retry-unknown
```

Повтор Telegram в этом случае может создать дубликат сообщения. Принятая статья
остаётся опубликованной независимо от статуса уведомлений.

## Резервная копия и перенос

```sh
python seo.py --project "../my-seo-state" backup "../seo-state-backup.zip"
```

Команда сохраняет согласованный снимок SQLite и личные рабочие файлы, исключая
`.env`. Архив всё равно содержит закрытую фактуру, черновики и данные сайта:
не размещайте его в публичном репозитории и храните защищённо.

Отдельно резервируйте `.env` в хранилище секретов, сайт и `state_dir` bridge.
Один архив контроллера не содержит весь сайт и серверные квитанции. При переносе:

1. Остановите новые старты и завершите активную операцию.
2. Перенесите снимок контроллера, согласованные файлы сайта и квитанции bridge.
3. Восстановите ключи, абсолютные пути, доступы и тот же релиз программы.
4. Выполните `doctor`, `status` и сверку незавершённых публикаций.
5. Оставьте только одно расписание и включите его после контрольного результата.

Новый запуск не должен считать старую непринятую операцию новой статьёй.
Обновляя пакет, сначала сохраните снимок и прочитайте изменения формата данных.
Не копируйте в личный профиль пустую конфигурацию поверх действующей.
